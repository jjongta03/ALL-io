# 로그인 없는 방문자 이용

2026-11-15 사용자 요청에 따라 로그인 폼·버튼·로그아웃 버튼과 비밀번호 로그인 API를 제거했다. 처음 접속하면 브라우저의 방문자 연결을 자동으로 준비하고, 신규 방문자는 사장님 정보 입력부터 시작한다. 기존 브라우저는 입력했던 단계와 대시보드로 이어진다.

## 데이터와 권한

- 방문자별로 별도의 `OWNER` 계정과 256-bit 무작위 세션을 자동 생성한다. 공용 관리자 계정이나 공용 사업장을 사용하지 않는다. 기존 관리자·발급 계정·사업장 데이터는 삭제하거나 다른 방문자에게 넘기지 않는다.
- 방문자 계정은 `is_guest=true`, `is_demo=false`, 비밀번호 없음이다. DB 제약으로 방문자 계정의 ADMIN 전환과 비밀번호 설정도 거절한다. 관리자 API의 ADMIN 검사와 모든 자원의 서버 소유권 검사는 유지한다.
- 브라우저 쿠키는 HttpOnly·SameSite=Lax, 운영 HTTPS에서는 Secure이며 30일간 유지한다. DB에는 토큰 해시만 저장한다. 쿠키를 지우거나 다른 브라우저·기기를 쓰면 새 방문자로 시작하며, 이전 자료의 자동 복구·기기 간 동기화 기능은 제공하지 않는다.
- 쿠키가 차단된 경우에는 무한 재접속 대신 쿠키 허용 안내와 재시도 버튼을 보여 준다. 기술용 방문자 이메일은 입력 화면이나 마이페이지에 표시하지 않는다. 사장님 기본정보와 알림 이메일 입력은 기존 기획대로 유지한다.
- 실제 서비스에서도 방문자 세션만 생성하며 가상 규칙을 등록하지 않는다. 외부 API와 이메일 발송 설정은 이번 변경으로 켜지지 않는다.

## 접속 경로

`/`와 `/start`에서 자동 연결을 준비한다. 보호된 화면에 바로 접속해도 `/start?next=...`에서 방문자 연결 후 원래 화면으로 이동한다. 내부의 허용된 화면만 복귀 대상으로 사용할 수 있다. 예전 `/login` 링크는 `/start`로 리디렉션하므로 로그인 폼이 나오지 않는다.

`POST /api/visitor`는 허용된 Origin이 필요하다. 기존 유효 세션이 있으면 재사용하고, 없을 때만 방문자를 생성한다. 소유자 ID·역할 등을 입력으로 받지 않는다. `POST /api/session` 비밀번호 로그인은 404다. `DELETE /api/session`은 쿠키 폐기 용도로만 유지하며 화면에는 로그아웃 버튼을 노출하지 않는다. 일반 자원 API는 방문자 연결 쿠키가 없으면 계속 401을 반환한다.

새 `0007_visitor_access.sql`은 기존 행을 보존하며 방문자 구분·역할 제약만 추가한다. 서버 시작은 마이그레이션과 암호화 키 확인만 실행하며 초기 로그인 계정을 추가 발급하지 않는다. 기존 Render의 초기 계정용 환경 변수는 이 코드에서 사용하지 않는다. 암호화 키와 DB 연결 값은 유지한다.

## 검증

`npm run check`, `npm run format:check`, `npm run build` 및 실행 중인 로컬 서버에 `npm run smoke:access`, `npm run smoke`, `npm run smoke:workspace`를 실행한다. `smoke:auth`는 기존 명령 호환을 위해 방문자 검증의 별칭으로 유지한다. 계정 fixture 준비는 필요하지 않다.

방문자별 계정·토큰 분리, 30일 만료, 기존 계정 보존, 방문자의 관리자·다른 사용자 자원 접근 차단, 잘못된 Origin 차단, 입력 화면 이동과 예전 로그인 경로의 자동 이동을 확인한다. 공개 사이트에는 검증한 커밋을 수동 배포한 뒤 브라우저에서 자동 접속과 로그인 폼 부재를 다시 확인한다.
