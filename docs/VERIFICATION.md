## 자동 검증 범위

- 시뮬레이션의 급여 경계·원본 불변·보험 인원 분리·입력 범위·데모 차단.
- Jev typed 응답 검증, 402/429/5xx/잘못된 응답·비활성 처리, 저신뢰·충돌·보류 및 원문 부족 경로.
- 분류 후 PENDING 상태 유지·이력 보존, 질문 소유권·미답변 접수, 이전 D-1 취소와 D-3 예약.
- HTTP에서 시뮬레이션 저장 불변·사용자 격리, FAQ·분류·API 현황 응답·화면 HTML 확인.
- 후속 브라우저 QA: 급여 변경 시 비교 결과 1개와 빨간 표시 확인, 저장된 인원·결과 유지, 서류 FAQ 응답, 검수 분류 후 승인 대기 유지, API 현황의 외부 요청 0회 표시 확인.
- 최종 빌드의 선택적 국세청 조회 입력과 미설정 버튼 비활성 확인. 좁은 화면에서 시뮬레이터·API 현황 배치와 가로 넘침 없음 확인(실측 CSS 폭 339px).

- 임계값 미만 비교의 T-1/T/T+1, 날짜 경계, null의 3값 논리.
- 현재 인원과 보험별 산정 인원 분리, 고용보험/국민연금 이력 분리.
- 현재 사업장 정보와 가정 계획의 분리·입력 스냅샷 보존.
- 미승인·가상 운영 규칙·유효기간 밖·지원 범위 밖 처리.
- 소유권 위반 요청 차단, 비밀번호 salt·검증, 세션 토큰 해시·폐기.
- 할 일 완료 상태 유지, 날짜 변경·알림 중지·계획 취소 시 예약 갱신.
- 중복 예약 방지, 로컬 보관함 한 번 저장, 불명확 전송 재시도 억제.
- 검수 승인과 재평가, 이미 처리한 검수 충돌, 게시 중지·되돌리기.
- 공식 URL 호스트 경계, 외부 연동 비활성 시 네트워크 호출 없음.
- 스티비 200을 접수로만 취급하고 치환값 HTML 이스케이프.
- AI 근거 구간의 원문 일치 검사, 모델의 검수 완료 표시 무시.
- 운영 설정에서 로컬 DB·데모·HTTP 설정 거절.
- 호스트의 다른 프로젝트 DATABASE_URL을 재사용하지 않음.

## 실제 검증하지 않은 것

- 로그인된 Miro의 최신 보드 내용.
- 실제 두루누리 등 제도의 완전한 적용 조건과 보험별 예외.
- 실제 국세청·Liner·스티비·채널톡 계정의 권한·요금·API 성공.
- 실제 이메일 수신·반송·수신 거부 동기화.
- 외부 PostgreSQL 서버, Docker Compose, Render 계정 배포.
- 실제 고객 개인정보 처리·운영 규모에서의 부하와 복구.

제도·API는 **구조와 연결 경계를 준비한 상태**이며 검증 완료로 표현하지 않는다. 운영 전 확인 항목은 `PRODUCTION.md`를 따른다.
