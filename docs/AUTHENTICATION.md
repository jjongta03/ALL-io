# 현재 변경 사항

2026-11-15 후속 요청으로 로그인 화면·비밀번호 로그인 API를 제거했다. 현재 동작은 [VISITOR-ACCESS.md](VISITOR-ACCESS.md)를 따른다. 아래는 이전 발급 계정 로그인 구현 기록이다.

# 발급 계정 로그인

2026-11-15 요청에 따라 이메일·비밀번호로 **이미 발급된 계정만** 로그인한다. 공개 회원가입은 제공하지 않는다. 기존 운영자 계정 발급 CLI와 소유권·역할 검사를 유지한다.

## 사용자 흐름

1. 첫 화면에서 바로 로그인하거나 상단의 `로그인`을 눌러 `/login`으로 이동한다.
2. 발급받은 이메일과 비밀번호를 입력한다. 비밀번호 보기/숨기기, 로그인 중 표시, 입력 오류와 인증 실패 메시지를 제공한다.
3. 로그인하면 기본적으로 `/dashboard`로 이동한다. 보호된 화면에서 로그인으로 이동한 경우 허용된 원래 화면으로 돌아간다. 외부 URL·API·로그인 화면을 복귀 경로로 지정할 수 없다.
4. 세션은 7일간 유지한다. 로그아웃 시 DB 세션과 쿠키를 폐기한다. 만료된 세션의 로그아웃도 가능하다. 브라우저에서 보호된 API가 401을 반환하면 로그인 화면으로 이동한다.
5. 로그인된 계정 이메일을 마이페이지에 표시한다. 다른 계정의 사업장·프로젝트에 접근할 수 없으며 운영자 API는 ADMIN만 사용할 수 있다.

공개 회원가입, SNS 로그인, 이메일 인증, 비밀번호 변경/재설정, MFA는 이번 요청 범위에 포함하지 않았다. 계정 발급 및 초기 비밀번호 확인은 서비스 관리자가 담당한다. 최신 ALL-IO PC 웹과 통합했으며 로그인 후에는 사업장 대시보드를 연다.

## 계정 발급

앱을 중지한 상태에서 실행한다. 로컬 PGlite는 한 번에 한 프로세스만 접근할 수 있다.

```powershell
npm run setup
npm run user:create -- owner@example.com OWNER
```

이메일과 무작위 초기 비밀번호는 Git에서 제외된 `data/account-UUID.txt`에 기록한다. 비밀번호를 명령행 인수로 전달하거나 로그에 출력하지 않는다. 파일은 공개·커밋하지 않고 대상 사용자에게 안전하게 전달한다. ADMIN이 필요한 경우 관리자가 CLI에 ADMIN을 명시한다. 로그인 요청으로 역할을 지정하거나 변경할 수 없다.

## API 계약

| 요청                  | 동작                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------- |
| `POST /api/session`   | `{email,password}`. 이메일 앞뒤 공백과 대소문자를 정규화한 뒤 발급 계정만 인증. 성공 `{ok:true}` 및 세션 쿠키 |
| `GET /api/me`         | 로그인한 계정의 id·이메일·역할·데모 여부. 비밀번호 해시·세션 토큰은 반환하지 않음                             |
| `DELETE /api/session` | 현재 세션 폐기·쿠키 제거. 로그인 여부와 관계없이 `{ok:true}`                                                  |

쓰기 API는 허용된 Origin이 필요하다. 잘못된 형식은 422, 잘못된 이메일/비밀번호는 동일한 401 `INVALID_CREDENTIALS`, 반복 시도 초과는 429 `LOGIN_RATE_LIMITED`를 반환한다. 발급받지 않은 이메일과 비밀번호 불일치를 구별해 알려주지 않는다. 데모 계정은 비밀번호 로그인할 수 없고 로컬 데모 버튼으로만 시작한다.

비밀번호는 무작위 salt를 사용한 scrypt 해시로 저장한다. 세션 쿠키는 HttpOnly·SameSite=Lax이며 운영 HTTPS에서 Secure를 설정한다. DB에는 토큰의 SHA-256만 저장한다. 로그인 성공 시 쿠키를 새 토큰으로 교체하고 같은 브라우저의 이전 세션을 폐기한다. 다른 기기의 세션은 유지한다.

계정별 15분 창에서 최대 8번의 로그인 시도를 허용한다(성공·실패 모두 포함). 제한 상태는 `0006_login_attempts.sql`의 DB 테이블에 저장하므로 앱 재시작·여러 서버 인스턴스에 걸쳐 유지한다. 제한 키는 정규화한 이메일의 해시다. 별도로 프로세스별 전체 요청 제한이 있으며, 운영에서는 프록시/게이트웨이의 전체 트래픽 제한도 검증해야 한다. 오래된 `login_attempts`의 보관·정리는 운영 정책에 맞춰 수행한다.

## 로컬 검증

외부 연동이 꺼진 로컬 PGlite 데모 전용 합성 계정으로 검증한다. 계정·비밀번호·세션 토큰은 ignored `data/auth-smoke-fixture.json`에만 저장하며 출력하지 않는다. 실제 사용자 계정을 사용하지 않는다.

```powershell
# 앱 중지 상태. 실제 APP_URL, LOCAL_DATABASE_PATH에 맞춰 실행
npm run setup
npm run smoke:auth -- prepare
# 서버를 시작한 다음 별도 터미널에서 실행
npm run smoke:auth
npm run smoke
npm run smoke:workspace
```

스모크는 반복 시도 제한까지 검사하므로 재검증할 때는 앱을 끄고 `prepare`로 새 합성 계정을 발급한다. `prepare`는 이전 계정이나 사용자 데이터를 삭제하지 않는다. 운영/외부 DB/실제 이메일 환경에서는 실행하지 않는다.

전체 검사: `npm run check`, `npm run format:check`, `npm run build`. 로그인 테스트는 발급 계정·오류 응답·Origin·반복 제한·세션 교체/만료/폐기·복귀 URL·다른 계정의 사업장 접근 및 ADMIN 권한 차단을 포함한다. 실제 계정 파일럿 전에는 HTTPS 쿠키, PostgreSQL 동시 요청, 계정 회수·비밀번호 재발급 운영 절차를 추가로 검증한다.

검증 기록(2026-11-15): 전체 테스트 94개, 형식 검사, 배포용 빌드와 로그인·기존·v2 HTTP 스모크 통과. 로컬 PC 브라우저에서 입력칸·로그인 버튼의 가로 넘침이 없고 비밀번호 보기/숨기기 전환이 동작함을 확인했다. 합성 DB는 ignored `data/login-smoke`, 화면 캡처는 ignored `artifacts/login-desktop.png`다. 실제 사용자 자격 증명·외부 이메일·배포는 사용하지 않았다.

원격 `f3b2189`의 ALL-IO PC 웹을 병합하면서 기존 크림색 카드·녹색 배경·글꼴과 화면 경로를 보존했다. 로그인 복귀 대상은 v2 사업장 화면과 기존 채용 계획 화면을 모두 포함한다. 통합 후 로그인·기존·v2 HTTP 검증(화면 24개 포함)을 다시 통과했다.
