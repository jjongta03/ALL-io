# Render 무료 체험 배포

2026-11-15 사용자가 서버 배포와 무료 체험 구성을 요청했다. 기존 Render 서비스는 수정하지 않고 `allio-postgres-trial` PostgreSQL 17을 싱가포르 리전에 생성했다. 무료 DB 만료 예정일은 2026-12-15(한국시간)이다. 웹 서비스는 `allio-web-trial`, `free` 플랜으로 준비한다. 유료 서비스·Cron은 생성하지 않는다.

## 배포 구성

- 저장소 `main`의 `render.yaml`을 사용한다. 기존 무료 DB를 Blueprint에 편입하고 같은 리전의 웹 서버에 비공개 연결 문자열을 바인딩한다. DB 비밀번호를 소스나 채팅에 기록하지 않는다. DB의 외부 네트워크 접속은 허용하지 않는다.
- `APP_ENV=production`, `APP_MODE=live`. 공개 데모 세션 생성과 가상 혜택 규칙 사용을 허용하지 않는다. 기존 로컬 데이터와 실제 사용자의 계약서는 업로드하지 않는다.
- 실제 도메인은 Render가 제공한 `RENDER_EXTERNAL_URL`을 사용한다. 필요하면 명시적 `APP_URL`로 재정의한다. 요청 헤더로 Origin 허용 범위를 결정하지 않는다.
- 빌드는 `npm ci --include=dev && npm run build`, 시작은 `npm run deploy:start`다. Render의 `PORT`와 `0.0.0.0`으로 서버를 시작한다. 무료 플랜에서 제공하지 않는 pre-deploy 명령 대신 시작 전에 마이그레이션을 실행한다.
- PostgreSQL 마이그레이션은 단일 트랜잭션과 advisory lock으로 중복 시작을 직렬화하고, 기존 체크섬 검사를 유지한다. 기존 마이그레이션 파일을 수정하지 않는다.
- 최초 배포 때 발급한 운영 계정은 보존한다. 후속 로그인 제거 요청에 따라 현재 서버 시작은 새 로그인 계정을 발급하지 않고, 브라우저별 방문자 OWNER 세션으로 연결한다. 이전 초기 계정 환경 변수는 사용하지 않는다.
- 계약서 암호화 키는 Render에서 생성한 `CONTRACT_ENCRYPTION_KEY_BASE64` 256-bit 값이다. 기존 64자리 hex `CONTRACT_ENCRYPTION_KEY`도 지원하되 동시에 설정하면 거절한다. 재배포할 때 이 키를 지우거나 다시 생성하지 않는다.
- 키 생성 및 로그인 계정 발급은 실제 이메일 발송을 수반하지 않는다. 외부 API 키는 비어 있고 이메일은 로컬 보관, Liner 검색/초안·계약서 인식·스티비 동기화는 비활성이다. 실제 조건을 검수·승인하기 전에는 지원사업이 비어 있을 수 있다.
- 초기 배포 이후 자동 배포와 Blueprint 자동 동기화는 꺼 둔다. 변경된 소스·설정을 검토하고 명시적으로 배포한다.

## 운영자 접근

사용자는 로그인 없이 바로 접속한다. 기존 관리자 데이터와 권한은 일반 방문자에게 공개하지 않는다. [현재 방문자 접속과 권한 경계](VISITOR-ACCESS.md)를 따른다.

## 무료 체험 제한

무료 웹 서버는 유휴 상태에서 절전되므로 첫 접속이 느릴 수 있다. 무료 사용 시간과 전송량은 같은 Render 워크스페이스의 기존 서비스와 공유한다. 무료 PostgreSQL은 생성 후 30일에 만료되며, 영구 운영용 데이터베이스가 아니다. 만료 전 필요한 데이터를 백업하고 지속 운영 여부와 예산을 결정한다. 이번 요청으로 유료 플랜 업그레이드나 추가 비용을 승인한 것으로 취급하지 않는다.

## 배포 검증과 상태

로컬에서는 `npm run check`, `npm run format:check`, `npm run build`, 기존·v2·로그인 HTTP 스모크를 확인한다. 운영 초기화 테스트는 최초 계정 발급·재시작 시 비밀번호 보존·가상 규칙 미등록·Render Origin·암호화 키를 포함한다.

실제 공개 서버에서는 배포 성공 상태, HTTPS `/api/health`, `/login`, 비로그인 자원 접근 401, 데모 세션 차단, 잘못된 Origin 차단과 DB 마이그레이션·최초 계정 생성 상태를 확인한다. 제공자 상태가 성공하거나 실제 HTTPS 응답을 확인하기 전에는 배포 완료로 보고하지 않는다.

## 로그인 제거 후속 배포

브라우저별 방문자 접속 변경을 같은 웹 서버에 배포했다. 기존 DB·암호화 키·무료 플랜·자동 배포 비활성 설정은 보존했다.

- 최종 배포 `dep-dbscsprl550s73842i10`, 실행 커밋 `54767f816e73345aa048ec267d1e39166b42b36d`, 2026-11-15 06:12(한국시간) `live` 완료.
- 첫 배포는 live 표기와 실제 이전 화면 응답이 달라 빌드 캐시를 비운 재배포를 진행했다. 최종 성공은 제공자 상태 외에 공개 HTTPS 응답으로 확인했다.
- 테스트 **115개**, 형식 검사, 빌드와 로컬 방문자·기존·v2 HTTP 스모크를 통과했다. 로컬 실제 브라우저에서 루트 접속 → 자동 세션 → 사장님 정보 입력 화면 이동을 확인했다.
- 공개 HTTPS에서 자동 방문자 생성·기존 세션 재사용·Secure/HttpOnly 쿠키, 서로 다른 OWNER 방문자, 빈 사업장 분리, 관리자 접근 403, 잘못된 Origin 403, 비밀번호 로그인 404, 예전 로그인 URL의 자동 접속 이동을 검증했다. 실제 사용자 자료나 외부 이메일은 생성하지 않았다.
- 현재 사이트는 [루트 주소](https://allio-web-trial.onrender.com)로 바로 사용한다. 비밀번호가 필요하지 않다.
