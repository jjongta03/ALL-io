## 디자인 적용

- Figma의 크림색 카드, 녹색 그라데이션, 카드 28px·버튼 18px 반경, PC 80px 여백, 800:456 / 2열 / 3열 배치를 적용했다.
- `@fontsource/noto-sans-kr`의 400·700 글꼴과 `public/figma/`의 화면별 SVG를 로컬에서 제공한다. 임시 Figma 자산 URL을 런타임에서 참조하지 않는다.
- 배경 SVG의 원래 크기 1180×980, 710×740을 유지한다. 작은 화면에서는 카드가 세로로 배치된다.
- 현재 백엔드 계약에 맞춰 알림톡을 이메일로 표시한다. 디자인의 지원금·직원·일정 예시 수치는 하드코딩하지 않는다.
- 신규 사용자는 빈 상태부터 시작한다. 저장된 값과 준비된 가상 데모 규칙으로 동작하며 실제 제도의 자격이나 법정 기한으로 표시하지 않는다.

## 서버 변경

`DELETE /api/v2/projects/:id`를 추가했다. 요청 본문은 `{ "confirm": true }`이며 기존 Origin·인증 검사와 소유권 검사를 적용한다. 사업장 잠금 아래 프로젝트·단계·연결 알림·로컬 보관함을 삭제하고 감사 기록을 남긴다. 정책과 불변 평가 스냅샷은 유지한다. 실제 신청 기관의 접수를 취소하는 기능은 아니다.

프로젝트 조회의 기존 SQL 반환 타입에 `title`, `TaskTemplate`을 명시했다. 데이터베이스 마이그레이션과 기존 판정 로직은 변경하지 않았다.

## 검증

- `npm run check`: 타입 검사와 77개 테스트. 프로젝트 삭제의 소유권·연결 데이터 정리·평가 보존·재시작 검증 포함.
- `npm run build`: 프로덕션 빌드.
- `npm run smoke`: 기존 API 흐름.
- `npm run smoke:workspace`: v2 API, 화면 경로 24개, 잘못된 경로 404, 프로젝트 삭제의 Origin·명시적 확인·소유권 검증.
- 브라우저 합성 데이터: 최초 입력→직원 직접 등록→진단→혜택 상세→프로젝트 시작→체크 완료 및 진행률 반영, 반복 서류 등록·수정, 프로필 날짜 저장, 퇴사 모달 취소.
- 1440px PC 및 375px·320px 모바일 확인. 대시보드·마이페이지에서 가로 넘침 없음. 배경 자산 로딩과 렌더링 크기 확인.

## 기존 백엔드의 한계

- 실제 외부 계약서 인식·스티비 발송은 키와 계정 설정 이후 검증해야 한다. 비활성 상태에서는 수동 입력과 로컬 보관 경로를 사용한다.
- 디자인의 일반적인 신고 업무 예시는 법정 기한으로 자동 생성하지 않는다. 반복 서류는 사용자가 확인한 업무와 날짜를 등록한다.
- 프로젝트의 필요 서류는 단계별 안내·신청 사이트로 연결한다. 일반 첨부파일 보관 API가 없어 프로젝트 문서 파일 저장 기능을 새로 제공하지 않는다. 직원 근로계약서 원문 보관·다운로드는 기존 API에 연결했다.
- 급여 변화 비교는 디자인과 같이 준비 중으로 표시한다. 직원별 실제 시급·근로시간 수정은 동작한다.

## 최초 진입 흐름

01-1의 이름·생년월일·휴대전화·알림 이메일은 필수다. ‘다음’을 눌렀을 때 누락 항목이나 잘못된 형식을 하단 고정 영역에 표시하고 이동·저장을 차단한다. 휴대전화의 ‘선택’ 표기를 제거했으며 이메일은 직접 입력·수정할 수 있다. 이메일 수신 동의는 선택 사항이다. 새로운 입력 흐름의 단계 저장은 서버에서도 필수 정보를 검증한다.

알림 이메일은 프로필에 저장하며 로그인 계정 이메일은 바꾸지 않는다. 알림 발송·주소록 동기화·외부 수신 거부 조회에 저장된 알림 이메일을 사용한다. 이메일을 바꾸면 이전 주소 해지와 새 주소 동기화 작업을 분리하고, 이미 다시 사용 중인 주소의 오래된 해지 요청은 취소한다. `0006_notification_email.sql` 마이그레이션을 추가했다. 실제 외부 호출은 하지 않고 전송 모의 테스트로 확인했다.

01-1 사장님 → 01-2 사업장 → 01-3 지난 사업기록 → 01-4 직원 명단 확인 후 대시보드로 이동한다. 입력 중에는 상단의 대시보드·지원사업·마이페이지 메뉴를 숨긴다. 미완료 계정의 화면 직접 접근은 서버에서 저장 단계로 되돌리며, 직원·계약서 등록은 4단계에서 접근할 수 있다. 임시 저장의 `completed` 상태와 실제 프로필·직원 명단 확정을 함께 확인한다. 기존 완료 계정은 계속 대시보드를 사용한다.

각 단계 저장이 성공한 다음 이동하며, 마지막 완료 시 프로필과 사업장·직원 명단을 저장하고 기존 서버 진단 결과를 조회한다. 이미 완료한 사용자가 입력을 다시 시작할 때에는 오래된 초안 대신 현재 저장 정보를 처음 보여 준다. 첫 방문 화면·단계 복귀·완료 전 진입 차단·완료 후 입력 업종 반영을 HTTP 검증에 포함했고, 브라우저에서 1→2→3→4→대시보드 이동을 확인했다.

GitHub 푸시와 외부 배포는 하지 않았다.

마이페이지 하단의 ‘기존 채용 계획’, ‘운영자 검수’, ‘API 사용 현황’ 진입 메뉴는 화면 피드백에 따라 제거했다. 하단에는 로그아웃만 표시한다. 기존 경로와 백엔드 API는 유지한다.

대시보드의 ‘정보 수정’ 버튼을 제거했다. 사업장이 없는 사용자의 등록 버튼은 유지한다. 페이지 전환 시 스크롤바 유무로 발생하던 15px 가로 이동은 루트의 `scrollbar-gutter: stable`로 방지하고, 메뉴의 기본 테두리 공간을 확보했다. 1089px에서 주요 메뉴 세 화면의 위치가 동일하며, 375px에서도 메뉴 전환 전후 위치·크기가 동일함을 확인했다.

## 체크리스트 화면 피드백 반영

- 항목별 설명 문구와 눈에 보이는 ‘준비 목표일’ 제목을 제거했다. 날짜 입력의 접근성 이름은 유지한다.
- 체크박스와 제목을 왼쪽부터 같은 줄에 배치하고 여백을 줄였다. 1089px 화면에서 항목 높이는 약 100px이며 375px 화면에서도 가로 넘침이 없다.
- 날짜 편집·저장과 완료 체크 동작은 기존대로 유지한다. 타입 검사·77개 테스트·프로덕션 빌드를 통과했다.

## 발급 계정 로그인 통합

발급 계정용 `/login` 화면과 첫 화면의 로그인 폼을 연결했다. 로그인 후 대시보드 또는 요청했던 화면으로 복귀하며, 마이페이지 로그아웃은 `/login`으로 이동한다. 회원가입은 제공하지 않는다. [계정 발급·세션·검증](AUTHENTICATION.md)을 참고한다. 기존 ALL-IO 화면과 프로젝트 삭제 기능을 보존했다.
